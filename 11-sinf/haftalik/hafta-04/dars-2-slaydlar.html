01

REST tamoyillari va Resurs tushunchasi

Mijoz va server o'rtasida ma'lumot almashishning universal me'moriyligi

1-qism: REST nima va URL qanday to'g'ri yoziladi.

REST'ning 5 asosiy ustuni

1. Client-Server & Stateless

Mijoz interfeysga, server ma'lumotlarga javobgar. Server har bir so'rovni alohida (stateless) ko'radi, sessiya holatini xotirada saqlamaydi.

2. Cacheable & Uniform Interface

Javoblar keshlash belgisi bilan keladi. Barcha resurslar yagona qoidalar (URI, HTTP metodlar, JSON) asosida boshqariladi.

Stateless xususiyati serverning gorizontal masshtablanishiga (scale out) imkon beradi.

URI Dizayni: Resursga yo'naltirilgan URL

Qoida: URL da «nima?» (resurs nomi — ko'plikda ot), HTTP metodida esa «nima qilish?» (harakat) belgilanadi.

Ierarxik va Filtrli URL loyihalash

Resurslar bog'liqligi

Ichki resurslar ota resurs ostiga joylashtiriladi:

  • GET /authors/15/books — 15-muallifning kitoblari
  • POST /orders/ORD-1/items — buyurtmaga tovar qo'shish

Filtrlash va Saralash (Query)

Filtr, sahifalash va tartib parametrlar orqali uzatiladi:

  • GET /books?genre=fiction&sort=year_desc
  • GET /books?page=2&limit=20
Query paramlar (so'roq belgisidan keyin) hech qachon asosiy resurs manzilini o'zgartirmaydi, faqat natijani filtrlaydi.
02

HTTP Metodlari va Idempotentlik

Har bir HTTP harakatining semantikasi, xavfsizligi va takrorlanuvchanligi

2-qism: CRUD amallari va HTTP metodlari mosligi.

HTTP Metodlari xarakteristikasi

Metod CRUD ma'nosi Xavfsiz (Safe)? Idempotent? Tipik status
GET Read (O'qish) Ha (ma'lumot o'zgarmaydi) Ha 200 OK
POST Create (Yaratish) Yo'q (yangi resurs) Yo'q (takrorlansa 2 marta yaratadi) 201 Created
PUT Replace (To'liq yangilash) Yo'q Ha (10 marta yuborsa ham bir xil holat) 200 OK / 204
PATCH Update (Qisman yangilash) Yo'q Odatda yo'q / Shartli 200 OK
DELETE Delete (O'chirish) Yo'q Ha (1 marta o'chgach, yana o'chirish holatni o'zgartirmaydi) 200 / 204 No Content
Idempotentlik: bitta so'rovni 1 marta yoki 100 marta yuborganda serverdagi yakuniy natija bir xil bo'lishi.

PUT va PATCH farqi

PUT — To'liq almashtirish

Resursning barcha maydonlari yuborilishi shart. Yuborilmagan maydonlar null bo'lib qolishi mumkin.

{
  "title": "Clean Code",
  "author": "Robert Martin",
  "price": 120000,
  "in_stock": true
}

PATCH — Qisman tahrirlash

Faqat o'zgargan maydonlargina yuboriladi. Qolgan barcha ma'lumotlar saqlanib qoladi.

{
  "price": 135000
}
Real loyihalarda PATCH ko'proq ishlatiladi, chunki tarmoq trafigini tejaydi.
03

Status kodlari va curl amaliyoti

Server javoblari bilan to'g'ri muloqot va sarlavhalar (Headers)

3-qism: HTTP status kodlari va curl amaliyoti.

Status kodlari guruhlari

2xx — Muvaffaqiyatli

  • 200 OK — So'rov bajarildi.
  • 201 Created — Yangi resurs yaratildi.
  • 204 No Content — Bajarildi, qaytadigan tana yo'q.

4xx — Mijoz xatosi

  • 400 Bad Request — Noto'g'ri format.
  • 401 Unauthorized — Autentifikatsiya yo'q.
  • 403 Forbidden — Ruxsat yetarli emas.
  • 404 Not Found — Resurs topilmadi.
  • 409 Conflict — Holat to'qnashuvi.
401 vs 403 farqini o'quvchiga aniq tushuntiring: 401 = «Siz kimsiz?», 403 = «Sizni taniyman, lekin bu yerga kirishga haqqingiz yo'q».

HTTP Sarlavhalari (Headers)

Content-Type

Mijoz yoki server yuborayotgan jism (body) qaysi formatdaligini bildiradi:

Content-Type: application/json

Accept

Mijoz serverdan qaysi formatdagi javobni kutayotganini belgilaydi:

Accept: application/json
Content Negotiation tushunchasi: server mijozning Accept sarlavhasiga qarab JSON yoki XML qaytarishi mumkin.

Keshlash: ETag va 304 Not Modified

304 kodi tarmoq trafigini 90% gacha tejaydi, chunki server tana (body) yubormaydi.

Terminalda curl bilan API sinash

# 1. Barcha kitoblarni olish
curl -X GET http://localhost:8000/api/v1/books -H "Accept: application/json"

# 2. Yangi kitob qo'shish
curl -X POST http://localhost:8000/api/v1/books \
  -H "Content-Type: application/json" \
  -d '{"title": "Clean Architecture", "author": "R. Martin", "price": 150000}'

# 3. Kitobni o'chirish
curl -X DELETE http://localhost:8000/api/v1/books/42 -v
-v (verbose) bayrog'i sarlavhalarni to'liq ko'rish uchun zarurligini ko'rsating.

Tezkor sinov: Status kodini toping

Qaysi vaziyatda qanday status kodi qaytarilishi kerak?

Vaziyat 1

Foydalanuvchi mavjud bo'lmagan /books/999 ga murojaat qildi.

Javob: 404 Not Found

Vaziyat 2

Yangi kitob muvaffaqiyatli bazaga qo'shildi.

Javob: 201 Created

Vaziyat 3

O'chirish muvaffaqiyatli bo'ldi, qaytarishga ma'lumot yo'q.

Javob: 204 No Content

O'quvchidan javoblarni so'rang.
