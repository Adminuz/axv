5. PROFESSIONAL IT DEVELOPMENT KASBI OʻQUV DASTURI
I-bob. Dasturiy ta’minot ishlab chiqish asoslari
Axborot texnologiyalari ekotizimi, dasturiy ta’minot hayotiy sikli (SDLC) va versiyalarni boshqarish tizimlari (Git/GitHub) ning qo‘llanilishi
IT ekotizimi qatlamlari (ilova–platforma–infratuzilma) va SDLC bosqichlari (talab, dizayn, kod, test, deploy, monitoring) tanishtiriladi. Git’da commit/branch/merge, GitHub’da PR va code review amaliy bajariladi. README va .gitignore yaratiladi, Issues/Projects bilan vazifa boshqaruvi ko‘rsatiladi. Ixtiyoriy: Actions (CI)ga kirish.
 Branching, Pull Request va code review metodologiyasi
Feature/release/hotfix tarmoqlari strategiyalari tanishtiriladi. Kichik, maqsadli commitlar va conventional commits qo‘llanadi. PR ochish (shablon, What/Why/How), checklist (funksional, xavfsizlik, test, hujjat) bilan ko‘rsatiladi. Code review etikasi, diff tahlili, konfliktlarni hal etish va merge siyosati amaliy bajariladi.
Clean Code va SOLID tamoyillari
Nomlash (aniq va izchil), formatlash, kichik funksiyalar va modulga ajratish prinsiplari ko‘rib chiqiladi. DRY/KISS/YAGNI yondashuvlari, kod hidi (code smells) va soddalashtiruvchi refaktoring usullari amalda qo‘llanadi. SOLID: SRP (bitta mas’uliyat), OCP (kengaytirishga ochiq), LSP (o‘rinbosarlik), ISP (ixcham interfeys), DIP (bog‘liqlikni inversiya) qisqa misollar bilan tushuntiriladi. Unit-test va hujjatlashtirish (README/docstring) orqali sifatni nazorat qilish ko‘rsatiladi.
 Loyihalash andozalari: Factory, Singleton, Observer
Factory — obyekt yaratishni abstraksiyalab, mijoz kodini aniq sinflarga bog‘lamaydi (creator method/abstract factory ssenariylari ko‘rsatiladi). Singleton — butun tizim bo‘yicha bitta nusxani kafolatlaydi; init tartibi, thread-safe implementatsiya va testlanishdagi cheklovlar tahlil qilinadi. Observer — “publish/subscribe” modelida hodisa (event)larni kuzatuvchilarga tarqatadi; couplingni kamaytirish, notifikatsiya ketma-ketligi va xotira oqimlari (detach) muhokama etiladi. Oddiy UML sxema va kichik kod misollari bilan qo‘llanish holatlari taqqoslanadi..
REST API va JSON asoslari
HTTP metodlari (GET/POST/PUT/PATCH/DELETE) va resursga yo‘naltirilgan URL dizayni tanishtiriladi. JSON tuzilmasi (obyekt, massiv, tiplar), status kodlar (200/201/400/401/404/500), header/Body, pagination va filtrlarning amaliy qo‘llanishi ko‘rsatiladi. Postman orqali endpointlar sinovdan o‘tkaziladi, xatolar formati (error schema), autentifikatsiya (Bearer/JWT) va CORS asoslari qisqa misollar bilan tekshiriladi.
Muloqot va jamoada ishlash ko‘nikmalari 
Jamoada rollar va mas’uliyatni aniqlash, maqsad/expectation’larni kelishish, aniq yozma va og‘zaki muloqot yuritish, feedback berish/qabul qilish hamda konstruktiv bahs-munozarani boshqarish o‘rganiladi. PR/issue yozish madaniyati, meeting etikasi, faol tinglash, konfliktni hal etish va umumiy qarorga kelish bo‘yicha amaliy mashqlar bajariladi.
Liderlik, mas’uliyat va vaqtni boshqarish
Shaxsiy mas’uliyat va mini-liderlik (task owner) tamoyillari, ustuvorlik belgilash (Eisenhower matritsasi), rejalashtirish va fokus texnikalari (time-boxing, Pomodoro) amalda qo‘llanadi. Delegatsiya, deadline boshqaruvi, OKR/KPI bilan natijani o‘lchash, risklarni erta xabar qilish va post-mortem orqali doimiy takomillashtirish mashq qilinadi.
II-bob. DevOps va uzluksiz integratsiya(CI) asoslari
Unix/Linux muhiti va tarmoq xizmati konfiguratsiyasi: SSH hamda Nginx reverse-proxyga kirish
Fayl tizimi iyerarxiyasi (/etc, /var, /usr), foydalanuvchi/huquqlar (chmod/chown), paket boshqaruvi (apt/yum) va servislar (systemctl) bilan tanishtiriladi. SSH uchun kalit juftligi (ssh-keygen), kalitni serverga joylash (ssh-copy-id), xavfsizlik (parolni o‘chirish, ufw/firewalld, AllowUsers, port sozlash) amaliy bajariladi. Nginx o‘rnatilib, server block va reverse-proxy (proxy_pass http://127.0.0.1:3000) sozlanadi; curl orqali sinov, loglar (/var/log/nginx/*), nginx -t va systemctl reload nginx bilan xatolarni diagnostika qilish ko‘rsatiladi.
Konteynerlashtirish nazariyasi va amaliyoti: Docker arxitekturasi, image lifecycle, tarmoq/volume
Docker mijoz–daemon modeli, image–container tushunchalari va qatlamli fayl tizimi tanishtiriladi. Image lifecycle: Dockerfile yozish, build/tag, push/pull, versiyalash va keshdan foydalanish ko‘rsatiladi. Tarmoq (bridge/host/custom subnet, port mapping) hamda volume (persistensiya, bind mount) amaliy qo‘llanadi. Izolyatsiya, resurs cheklovlari va xavfsizlik bo‘yicha tavsiyalar beriladi.
Uzluksiz integratsiya (CI) GitHub Actions platformasida: workflow dizayni va avtomatlashtirilgan sinovlar
on: push/pull_request triggerlari bilan YAML workflow tuziladi: jobs va steps, runs-on, strategy.matrix orqali ko‘p versiyada test. Lint/format, unit-test va build bosqichlari qo‘shiladi; actions/checkout, setup-* action’lari ishlatiladi. Kesh (actions/cache) va artefaktlar (upload-artifact) sozlanadi, status tekshiruvi (required checks) va PR bilan integratsiya amaliy ko‘rsatiladi.
III-bob. Bulut va joylashtirish (Cloud &amp; Deployment)
Uzluksiz joylashtirish (CD) va muhit o‘zgaruvchilari (env/secrets) boshqaruvi 
Git push → build → deploy zanjiri avtomatlashtiriladi (Vercel/Netlify/Render yoki GitHub Actions orqali). Staging/production muhitlari ajratilib, versiya/rollback strategiyalari (blue-green/rolling) ko‘rsatiladi. Konfiguratsiya koddan ajratiladi: .env fayllari, GitHub Secrets/Deploy secrets, runtime env’lar bilan ishlash. Maxfiy kalitlar uchun rotatsiya, kirish huquqlari (least privilege), audit loglari va xatoliklarni kuzatish amaliy bajariladi.
Bulut platformalariga kirish (AWS/Azure/GCP): xizmat sinflari va arxitektura tamoyillari
IaaS/PaaS/SaaS hamda FaaS (serverless) farqlari, global mintaqa–availability zone tushunchalari va shared responsibility modeli tanishtiriladi. Elastiklik, skalalanuvchanlik, yuqori uzluksizlik (SLA) va narxlash (pay-as-you-go, kvotalar) prinsiplari ko‘rib chiqiladi. VPC/VNet tarmog‘i, identifikatsiya va ruxsat (IAM), resurs teglash va kuzatuv asoslari beriladi; xizmatlar mosligi: EC2/Compute Engine/VM, S3/Blob Storage, RDS/Cloud SQL, Lambda/Functions misollarida ko‘rsatiladi.
AWS amaliyoti: EC2/S3/IAM yordamida minimal deploy
EC2 instansiya yaratiladi: AMI tanlash, key pair, security group (HTTP/HTTPS/SSH portlari) va user-data orqali avtomatik nginx/ilova starti. S3’da statik fayllar uchun bucket tashkil etilib, Block Public Access va Bucket policy sozlanadi (yoki CloudFront bilan tarqatish). IAM’da least privilege tamoyili: foydalanuvchi/rol, policy va instance profile bilan S3 ga cheklangan ruxsat beriladi. AWS CLI konfiguratsiyasi (aws configure), tag’lash, CloudWatch log/metrics orqali holatni kuzatish amaliy bajariladi.
Domen, DNS va SSL/TLS integratsiyasi
Domen ro‘yxatdan o‘tkaziladi, nameserverlar sozlanadi va asosiy DNS yozuvlari kiritiladi: A/AAAA (IP), CNAME (alias), TXT (tasdiq/ SPF), MX (pochta). Reverse-proxy (Nginx) bilan virtual host va proxy_pass sozlanadi. SSL/TLS uchun sertifikat olinadi (Let’s Encrypt/ACM), HTTP-01/DNS-01 tekshiruvlari bajariladi, avtomatik yangilash va chain to‘liqligi nazorat qilinadi. HTTPS majburiyligi, HSTS/redirect (301), kuchli shifrlash to‘plamlari hamda sertifikat muddati/rotatsiyasi amaliy tekshiriladi.
Bulut xavfsizligi va kirish nazorati
Least-privilege IAM (foydalanuvchi/rol/policy), MFA va vaqtinchalik tokenlar (STS) qo‘llanadi. Secrets/KMS bilan kalit va maxfiy ma’lumotlar boshqaruvi, rotatsiya tartibi ko‘rsatiladi. Tarmoq darajasi: Security Group, NACL, WAF/Shield. Audit va monitoring: CloudTrail/Config/GuardDuty. SCP/Policy Boundaries orqali cheklovlar, incident-response playbook hamda compliance talablari (log retention, verifiable trails) amaliy tekshiriladi.
IV-bob. Freelance va startap rivojlantirish
Freelancing ekotizimi va platformalar arxitekturasi (Upwork, Fiverr, Toptal, LinkedIn gig)
Platforma turlari, reyting/“trust” mexanizmlari, KYC/ToS talablari va komissiya modellari tushuntiriladi. Vakansiya qidirish va filtrlash (soha, daraja, byudjet, deadline), xavflarni boshqarish (scope creep, no-show, to‘lov xatari) ko‘rsatiladi. Profil semantikasi (sarlavha, “overview”, skill/tag, portfel havolalari) va platformaga xos algoritmik omillar tahlil qilinadi. Ixtiyoriy: “first 5 jobs” strategiyasi, nish (niche) tanlash va differensial taklif ishlab chiqish.
Portfolio, GitHub va case study ishlab chiqish metodikasi
Portfolio mazmuni “Problem → Solution → Result” narrativida tuziladi: kontekst, muammo, yondashuv, texnologiyalar, natija va havolalar keltiriladi. GitHub profili optimallashtiriladi: pin repos (3–6 ta), README.md (demo/skrinshet/GIF), badge’lar (build, test), LICENSE, CONTRIBUTING, CHANGELOG. Har bir loyiha uchun live-demo (Vercel/Render), docs/ papkasi, o‘lchovli metrikalar (tezlik, foydalanuvchi, kechikish) ko‘rsatiladi. Case study bir sahifalik shablon bilan rasmiylashtiriladi: maqsad, arxitektura skemasi, qarorlar asoslanishi, test/CI natijalari, keyingi reja.
Mijoz bilan muloqot, narxlash modeli, kontrakt va to‘lov jarayonlari
Brief/discovery orqali talablar aniqlanadi, yozma SOW (scope), deliverable, timeline va acceptance mezonlari kelishiladi. Narxlash strategiyalari taqqoslanadi: soatlik (rate, track) va fixed-price (milestone, risk buffer), change-request va scope-creep boshqaruvi belgilab olinadi. Kontrakt tarkibi: IP huquqlari, NDA, SLA, revisions, kafolat/qo‘llab-quvvatlash; invoicing va to‘lov kanallari (Payoneer/Wise), escrow va refund siyosati ko‘rsatiladi. Nizolarni hal etish tartibi, penalti/late fee hamda hujjatlashtirilgan yozishmalar (evidence) amaliy misollar bilan yoritiladi.
Startap yondashuvi: g‘oya → MVP → pitch (Lean Canvas, Value Proposition, backlog)
Muammo–bozor mosligini aniqlash uchun Lean Canvas to‘ldiriladi: muammo, mijoz segmentlari (ICP/persona), qiymat taklifi (UVP), yechim, kanallar, daromad xaritasi va asosiy metrikalar. MVP minimal funksiyalar bilan belgilab, 1-sprint backlog (3–5 vazifa) va validatsiya mezonlari (intervyu, A/B, foydalanish metrikalari) qo‘yiladi. Bozor va raqobatchilar tahlili asosida MVP’ni iterativ takomillashtirish, “must-have vs nice-to-have” ajratilishi ko‘rsatiladi. Pitch tuzilmasi: muammo, yechim, bozor hajmi, texnik yondashuv, traction/metrikalar, biznes modeli va ask (resurs/hamkorlik) — 3–5 daqiqalik taqdimot uchun vizual skema va demo havolasi bilan.
Omma oldida nutq so‘zlash va muvaffaqiyatli taqdimotlar o‘tkazish.
Tinglovchini tahlil qilish, maqsad va asosiy xabarni aniqlash, “hook–mantiqiy rivoj–CTA” tuzilmasida hikoyalash (storytelling) orqali kontentni qurish amaliy ko‘rinishda bajariladi. Slayd dizaynida minimalizm, kontrast, ierarxiya va vizual metaforalardan foydalanish, ovoz tembri, pauza, tana tili va sahna makonini boshqarish ko‘nikmalari mustahkamlanadi; trejlash va vaqtni boshqarish bo‘yicha repetitsiya usullari qo‘llanadi. Savol-javobni moderatsiya qilish, stress va sahna hayajonini yengish, texnik xatolar uchun B-reja, yakunda esda qoladigan “call-to-action” va ta’sirni baholash (feedback, recording) orqali uzluksiz yaxshilash yo‘lga qo‘yiladi.
Loyiha boshqarish va jamoaviy ishlash
Maqsad–natija iyerarxiyasi (vision → roadmap → sprint reja) asosida loyiha doirasi, vaqt va byudjet cheklovlari boshqariladi; stakeholder tahlili, risk reyestri, RACI/rol va mas’uliyatlar aniqlanadi. Jamoa jarayonlari Agile prinsiplariga tayangan holda rejalashtirish, kundalik sinxronlashuv, demo va retrospektiva orqali iterativ boshqariladi; vazifalar WBS → backlog → prioritetlash (MoSCoW/WSJF) bilan oqimga joylanadi. Hamkorlik Git, task-treker (Jira/Trello/ClickUp), kerakli hujjatlar (DoD/DoR, meeting notes) va kommunikatsiya protokollari orqali yuritiladi; konfliktlarni yechish, feedback madaniyati va “single source of truth” shaffoflikni ta’minlaydi. KPI/OKR va burn-down/burn-up vizuallari bilan monitoring yo‘lga qo‘yilib, o‘lchovlarga tayanib doimiy yaxshilash (continuous improvement) amalga oshiriladi.
Agile, Scrum, Kanban metodologiyasi
Agile qadriyatlari asosida iterativ ishlab chiqish yondashuvlari taqqoslanadi: Scrum’da rollar (Product Owner, Scrum Master, Team), artefaktlar (Product/Sprint Backlog, Increment, DoD) va sprint jarayoni (Planning, Daily, Review, Retrospective) amaliy ko‘rinishda qo‘llanadi. Kanban’da vizual oqim, WIP limitlari, cycle/lead time va bottlenecklarni aniqlash orqali uzluksiz yaxshilashga erishiladi; qiymatni tez yetkazish va shaffoflik ta’minlanadi.
Jira, Trello, ClickUp bilan ish jarayoni 
Jira/Trello/ClickUp vositalarida backlog yuritish, board sozlash (Scrum yoki Kanban), issue hayotiy sikli (To Do → In Progress → Done)ni boshqarish, label/priority/assignee/due date bilan rejalashtirish ko‘rsatiladi. Sprint boshqaruvi, burndown/velocity, Kanban metrikalari (cycle time, cumulative flow), avtomatlashtirishlar (Butler/Zapier), GitHub–CI/CD integratsiyasi va hisobotlar orqali jamoa samaradorligi o‘lchanadi hamda jarayonlar standartlashtiriladi.

9. PROFESSIONAL IT DEVELOPMENT KASBI TAVSIFI
9.1. Bitiruvchining kasbiy faoliyati sohalari
Professional IT development kasbi boʻyicha kasb-hunarga tayyorlash kursini toʻliq oʻzlashtirgan holda chuqur malaka talab etmaydigan ofis jihozlarini oʻrnatuvchi va ularga texnik xizmat koʻrsatuvchi sifatida korxonalarda, tashkilotlar, maktabgacha taʼlim muassasalari va umumiy oʻrta taʼlim maktablarida faoliyat koʻrsatadi. 
9.2. Bitiruvchining kasbiga muvofiq kasbiy faoliyat obyektlari
- turli tipdagi jihozlar va asbob-uskunalar;
- zamonaviy kompyuter dasturlari;
- zamonaviy drayverlar, simli tarmoq qurilmalari;
- simsiz tarmoq qurilmalari va sifatli xom ashyolar kiradi.
9.3. Professional IT development kasbiy faoliyat turlari
Professional IT development uchun ish oʻrnini toʻgʻri tashkil etish va asbob-uskunalarini toʻgʻri tanlash;

Mijoz bilan muloqot, narxlash modeli, kontrakt va to‘lov jarayonlari
 Brief/Discovery: talablarni aniqlash, savol-jadval (scope, cheklov, deadline, budjet) va risklarni erta yuzaga chiqarish.
SOW (Scope of Work): deliverable’lar, qamrovdan tashqari ishlar, timeline, acceptance kriteriy va kommunikatsiya chastotasini yozma belgilash.
Proposal anatomiyasi: shaxsiylashtirilgan intro, muammo→yechim, MVP/roadmap, metrik natija, narx variantlari va “next step”.
Narxlash modeli: soatlik (rate, time-tracking) vs fixed-price (milestone); change-request va risk buffer siyosati.
Milestone va rejalash: sprintlarga bo‘lish, demo/QA nuqtalari, deliverable bo‘yicha to‘lov triggerlari.
Scope creep boshqaruvi: har bir qo‘shimcha talabni CR (change request) bilan narx/vaqtga bog‘lab tasdiqlash.
Kontrakt bandlari: IP/Ownership, NDA, SLA, revisions limiti, qo‘llab-quvvatlash, warranty, late fee/penalti.
To‘lov mexanizmi: escrow (Upwork) yoki invoice (Payoneer/Wise); avans % va yakuniy to‘lov shartlari.
Hujjatlash va izchillik: yozma muloqot (chat/email)ni arxivlash, qarorlar logi, versiyalangan hujjatlar.
Muloqot etikasi: status update, timezone moslashuvi, aniq “expectation management”, risklarni oldindan xabar qilish.
Compliance &amp; xavfsizlik: KYC/ToS, PII/secretsni himoya qilish, havfsiz fayl almashish va rasmiy kvitansiyalar.
Nizo va qayta ko‘rib chiqish: dispute jarayoni, mediatsiya, partial refund ssenariylari va “project closure” cheklisti.
Startap yondashuvi: g‘oya → MVP → pitch (Lean Canvas, Value Proposition, backlog)
 Muammo identifikatsiyasi: og‘riq nuqtalarini (pain points) aniqlash, gap-intervyular orqali tasdiqlash.
ICP/Persona: ideal mijoz profili va segmentlarni aniq ta’riflash, ustuvor segmentni tanlash.
Lean Canvas: muammo, yechim gipotezasi, UVP, kanallar, daromad oqimi, xarajat tuzilmasi, asosiy metrikalar, raqobat ustunligi.
Value Proposition (UVP): mijozga beriladigan aniq qiymat, alternativalardan farq va “why now” dalili.
Raqobat tahlili: substitutlar/bozor xaritasi; differensiasiya va kirish to‘siqlari (barriers).
MVP skopi: “must-have” funksiyalarni minimal ko‘lamda belgilash; prototip vs ishchi versiya farqi.
Backlog tuzish: 1-sprint uchun 3–5 vazifa, “definition of done”, qabul (acceptance) mezonlari.
Validatsiya metrikalari: AARRR (acquisition, activation, retention, revenue, referral) va AB-test/kohorta kuzatuvi.
Texnik arxitektura tanlovi: monolith vs serverless, tez prototiplash uchun stack; narx–tezlik–xavfsizlik trade-off.
Go-to-market (GTM): kanallar (SEO, community, paid), ilk foydalanuvchilarni jalb qilish va “landing + waitlist”.
Pitch deck anatomiyasi: muammo, yechim, bozor (TAM/SAM/SOM), model, traction/metrikalar, roadmap, jamoa, ask.
Risk va huquqiy jihatlar: IP/licenziya, ma’lumotlar maxfiyligi, MVPdan keyingi shkalalash va monitoring rejasi.
