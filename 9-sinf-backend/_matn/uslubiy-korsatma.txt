1.4-rasm: Qo‘shimcha imkoniyatlarni belgilash
Ushbu oynada Python dasturlash tilini o‘rnatish jarayonidagi qo‘shimcha imkoniyatlar (Optional Features) ko‘rsatilgan. 1.5-rasm: Sozlamalarni tanlab, Install (o’rnatish) buyrug’ini berish.
 Ushbu oynada Python dasturlash tilini o‘rnatish jarayonidagi Advanced Options (kengaytirilgan sozlamalar) ko‘rsatilgan. Bu yerda Install Python for all users bandi belgilanishi tavsiya etiladi, bu Python’ni kompyuterning barcha foydalanuvchilari uchun o‘rnatadi. Add Python to environment variables bandi Python buyruqlarini buyruqlar satrida ishlatish imkonini beradi. Precompile standard library bandi esa Python’ning standart kutubxonalarini oldindan tayyorlab qo‘yiladi va dasturlarning tezroq ishga tushishini ta’minlaydi. O‘rnatish manzili esa standard holatda qoldiriladi va o‘rnatishni boshlash uchun Install tugmasi bosiladi.

1.47-rasm: match / case uchun soda misol

	•	case 3 – agar, kiritlgan son 3 ga teng bo‘lsa, “ Dastur yopildi ” xabari chiqadi;
	•	case _ - qolgan barcha kiritilgan natijalar uchun “ Noto‘g’ri tanlov ” xabari chiqadi.

DRY (Don’t Repeat Yourself) — dasturlashdagi eng muhim prinsiplardan biri. Mazmuni: bir xil mantiq (kod)ni bir necha joyda takror yozma; uni bitta joyga jamla (funksiya, klass, modul, konfiguratsiya), keyin hamma joyda shu “bitta manba”dan foydalan.

	•	xato chiqsa — 5 joyni ham tuzatishga to‘g‘ri keladi
	•	bir joy tuzatilsa, boshqasi unutilsa — bug paydo bo‘ladi
	•	kod uzayadi, o‘qish qiyinlashadi
	•	testlash va qo‘llab-quvvatlash qimmatlashadi
DRY qilinganda esa:
	•	o‘zgartirish bitta joyda

	•	testlash oson

3-bob haqida umumiy ma’lumot
Mazkur bobda PostgreSQL ma’lumotlar bazasini boshqarish tizimi va uning amaliy qo‘llanilishi bosqichma-bosqich o‘rgatiladi. Bob ma’lumotlar bazasi tushunchasi, uning turlari hamda MBBT (Ma’lumotlar bazasini boshqarish tizimi) haqida umumiy nazariy ma’lumot berishdan boshlanadi. SQL — strukturallangan so‘rovlar tili yordamida ma’lumotlarni boshqarish asoslari yoritiladi.
Shuningdek, PostgreSQL’ni o‘rnatish, yangi ma’lumotlar bazasi va jadvallar yaratish, asosiy ma’lumot turlari (data types) bilan ishlash ko‘nikmalari shakllantiriladi. CRUD amallarini (create, read, update, delete) bajarish, shuningdek, jadvalda cheklovlar va shartlar (constraints) qo‘llash orqali ma’lumotlar yaxlitligini ta’minlash masalalari amaliy misollar asosida tushuntiriladi.
Bob davomida jadvallar tuzilmasini o‘zgartirish (ALTER TABLE), so‘rovlarda filtrlar (WHERE) dan foydalanish, agregat funksiyalar (COUNT, SUM, AVG va boshqalar) hamda GROUP BY orqali guruhlash usullari o‘rganiladi. Bundan tashqari, bir nechta jadvallarni o‘zaro bog‘lash (JOIN) orqali murakkab so‘rovlar tuzish ko‘nikmalari rivojlantiriladi.
Bob yakunida o‘quvchilarda PostgreSQL muhitida mustaqil ishlash, ma’lumotlar bazasini loyihalash va SQL so‘rovlar yordamida ma’lumotlarni samarali boshqarish bo‘yicha mustahkam nazariy va amaliy bilimlar shakllantiriladi.

Asinxron dasturlash 
Oddiy dasturlashda (sinxron) kod ketma-ket ishlaydi: 1-ish tugamasdan 2-ish boshlanmaydi. Asinxronda esa ba’zi ishlar (ayniqsa internetdan ma’lumot olish, fayl o‘qish, baza bilan ishlash) kutish talab qiladi. Asinxron dasturlashda shu “kutish” vaqtida dastur bo‘sh turmaydi, boshqa vazifalarni bajarib turishi mumkin.
Oddiy misol (hayotiy):
	•	Sinxron: do‘konda 1 ta kassada 1 odam to‘lab bo‘lmaguncha keyingisi kutadi.
	•	Asinxron: bir nechta odam buyurtma beradi, kimnidir buyurtmasi tayyor bo‘lguncha boshqalarniki qabul qilinadi.
Nega kerak?
Web dasturlarda (API serverlarda) ko‘p foydalanuvchi bir vaqtda so‘rov yuboradi. Server har so‘rovda internet/baza javobini kutishi mumkin. Asinxron yondashuv:
	•	ko‘proq foydalanuvchiga xizmat qiladi,
	•	server “qotib qolmaydi”,
	•	tezroq va samaraliroq bo‘ladi.
Asinxron tushunchalar: async, await, event loop
	•	async def bilan yozilgan funksiya “asinxron funksiya” bo‘ladi.
	•	await — “shu ish tugaguncha kut, lekin boshqalarni bloklama” degani.
	•	event loop — vazifalarni navbat bilan boshqaradigan “dispatcher” kabi. Qaysi vazifa kutyapti, qaysi vazifa tayyor — shularni yuritadi.
Sinxron va asinxron farqini ko‘rsatish
Sinxron kutish (time.sleep)

	•	-rasm: time.sleep
Bu yerda time.sleep(2) dastur oqimini to‘liq to‘xtatadi. 2 soniya ichida boshqa hech narsa bajarilmaydi. Bu — bloklovchi (blocking) kutish.
Asinxron kutish (asyncio.sleep)

	•	-rasm: asynio.sleep
await asyncio.sleep(2) — bloklamaydigan kutish. Bu vaqt ichida event loop boshqa asinxron vazifalarni ishlatishi mumkin. asyncio.run(main()) asinxron dastur “dvigatelini” ishga tushiradi.

Autentifikatsiya (Authentication) — “Sen kimsan?”

	•	login + parol
	•	SMS kod
	•	token
	•	biometrik
Avtorizatsiya (Authorization) — “Senga nima mumkin?”
Foydalanuvchi kimligi tasdiqlangandan keyin, unga qaysi ruxsatlar berilishini aniqlash:
	•	oddiy user faqat o‘z profilini ko‘ra oladi
	•	admin hammani o‘chira oladi
Qisqa misol:
	•	Autentifikatsiya: “Ali” parol bilan kirdi 
	•	Avtorizatsiya: “Ali admin emas, demak o‘chira olmaydi”
Token — server bergan “ruxsatnoma”ga o‘xshash raqamli kalit.
HTTP so‘rovlar mustaqil (stateless). Har so‘rovda server “bu kim edi?” deb bilishi kerak. Token bo‘lsa:
	•	user bir marta login qiladi
	•	server token beradi
	•	keyingi so‘rovlarda user tokenni yuboradi
	•	server tokenni tekshiradi va ruxsat beradi
JWT (JSON Web Token) — ichida ma’lumot saqlaydigan token formati.
JWT odatda 3 qismdan iborat:
	•	Header
	•	Payload (ichidagi data: user_id, username, role, exp va h.k.)
	•	Signature (imzo) — token o‘zgarmaganini tekshirish uchun
JWTning asosiy foydasi:
	•	token ichidagi ma’lumotni server tekshiradi
	•	bazaga har safar “session” izlab yurmaydi (ko‘pincha)
Muhim: JWT ichidagi payload odatda shifrlanmagan, faqat imzolangan bo‘ladi. Shuning uchun token ichiga maxfiy parol yozilmaydi!
OAuth2 — autentifikatsiya/avtorizatsiya uchun standart (qoidalar to‘plami).
FastAPI’da ko‘p ishlatiladigan usul:
	•	OAuth2 Password Flow (username + password bilan token olish)

	•	X-Forwarded-Proto — HTTP/HTTPS ekanini bildiradi.
Oddiy misol: Ofitsiant oshxonaga faqat “osh” deb aytmaydi. “2 porsiya osh, 5-stol, achchiq bo‘lsin” deb to‘liq aytadi. Headerlar ham shunga o‘xshaydi.

	•	Qolgan hamma so‘rovlar backendga ketadi.

Load balancer — bu serverga kelayotgan ko‘p sonli so‘rovlarni bir nechta backend serverlar orasida taqsimlab beradigan mexanizm.
Oddiy qilib aytganda, load balancer:
	•	bitta serverga hamma yukni tashlamaydi,
	•	kelgan so‘rovlarni navbat bilan yoki holatga qarab bo‘lib yuboradi,
	•	serverlar haddan tashqari yuklanib qolishining oldini oladi.
Load balancer nima uchun kerak?
Agar saytga:
	•	foydalanuvchilar soni ko‘paysa,
	•	bitta backend server ishlamay qolsa,
	•	so‘rovlar og‘ir (hisob-kitob, fayl yuklash) bo‘lsa,
bitta server yetarli bo‘lmaydi. Shu sababli bir xil backenddan bir nechta nusxa ishlatiladi va yuk bo‘linadi.
